Anatomy

A visible label and useful guidance

The label names the value. Helper text explains format or consequence before the user encounters an error.

Use the name your team will recognize.

States

Disabled and readonly are different

Disabled values are unavailable. Readonly values remain focusable and can be selected or copied.

Managed by your administrator.

Select and copy this value when contacting support.

Developer reference

Implementation

Install from npm, import @nikba/design-system/css, and place this markup inside .nds-scope. JavaScript examples use the public package exports.

HTML · Example 1
<div class="nds-field">
  <div class="nds-field__label-row">
    <label class="nds-field__label" for="project-name">
      Project name
      <span class="nds-field__required" aria-hidden="true">*</span>
    </label>
  </div>
  <input
    class="nds-input"
    id="project-name"
    name="project-name"
    type="text"
    required
    aria-describedby="project-name-help"
  />
  <p class="nds-field__helper" id="project-name-help">
    Use the name your team will recognize.
  </p>
</div>

SwiftUI · Jetpack Compose · Experimental

Native Field

For iOS, link the local NikbaDesignSystem Swift package and import SwiftUI and NikbaDesignSystem; Onest is bundled. For Android, add NikbaTokens.kt and NikbaComponents.kt and import Compose Material Text and com.nikba.designsystem.*. Examples below belong inside your native view or composable, with application-owned state and actions.

Supply your value, validation error, and native focus binding. The error message takes precedence over helper text. Native input keeps ownership of editing and keyboard behavior.

SwiftUI · Field
NDSField("Name", helper: "Your display name", error: nameError, isFocused: nameFocused) {
    TextField("Your name", text: $name).focused($nameFocused)
}
Compose · Field
NDSField(value = name, onValueChange = { name = it }, label = "Name",
    helper = "Your display name", error = nameError)

Usage guidance

Write labels that survive without placeholders.

Use short nouns for labels, concise instructions for helper text, and specific recovery steps for errors.
