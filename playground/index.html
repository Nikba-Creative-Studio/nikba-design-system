Get started · npm

Install. Import. Build.

Use the stable npm package in your application. The examples below assume an ES module bundler such as Vite.

1. Install with npm

Terminal
npm install @nikba/design-system

2. Import CSS and configure your theme

JavaScript
import '@nikba/design-system/css';
import { setTheme, setGlassLevel } from '@nikba/design-system';

setTheme('frost'); // frost, mist or graphite
setGlassLevel('soft'); // off, soft or clear

3. Add your first component

HTML
<main class="nds-scope">
  <button class="nds-button nds-button--secondary" type="button">
    Preview project
  </button>
</main>

4. Initialize interactive components

JavaScript
import { initDialogs } from '@nikba/design-system';

// Run after the component markup is in the document.
const cleanup = initDialogs(document);

// Call cleanup() before removing the component.

Static components need CSS only. Interactive components such as Dialog, Select and Tabs also need their initializer; copy the matching HTML and JavaScript from the component reference.

Onest fonts are application-owned: load or self-host Onest separately. Read the foundations guide.

Shared source

Tokens flow from one place.

src/tokens/foundations.json generates the existing CSS token files, NikbaTokens.swift, and NikbaTokens.kt. Frost, Mist, and Graphite are available on all three platforms. On iOS, adaptive colors follow system appearance with Frost in light mode and Graphite in dark mode; Android selects the palette in its theme.

The first native consumer is localhost.md. Its iOS and Android apps use the shared components for catalog search, panels, badges, recovery actions, and content states. Product-specific navigation and identity stay in the app.

Get started · Native pilot

Add tokens and components to your app.

iOS supports a Swift package with bundled Onest; Android uses source files and an app-owned font resource. Native APIs are published as a pilot in release 1.1.0; the web library retains its stable API.

iOS · Swift Package Manager

  1. In Xcode, choose Add Package Dependencies, enter https://github.com/Nikba-Creative-Studio/nikba-design-system.git, and select Exact Version 1.1.0. MCP’s get_installation({ platform: "ios" }) returns remote and local installation options.
  2. Link the NikbaDesignSystem product to your iOS app target and import NikbaDesignSystem alongside SwiftUI.
  3. Use NDSTypography.font to register bundled Onest automatically. Request get_native_source({ platform: "ios", kind: "example" }) for a complete first screen with state and focus bindings.

The v1.1.0 release tag contains the Swift package and bundled font. For local development, use Add Local with this checkout. The older web-only v1.0.0 tag does not contain Package.swift.

SwiftUI

With SwiftPM, import the module as below. For the source-copy alternative, add NikbaTokens.swift and NikbaComponents.swift to the app and omit the module import. Components use adaptive Frost/Graphite colors and text styles that respond to the reader’s preferred size.

Swift · iOS 17+
import SwiftUI
import NikbaDesignSystem

struct WelcomeView: View {
    var body: some View {
        NDSCard {
            NDSBadge("Ready", tone: .success)
            Text("Welcome to Nikba")
                .font(NDSTypography.font())
            NDSButton(action: { /* Start your flow. */ }) {
                Text("Continue")
            }
        }
    }
}

Jetpack Compose

Add NikbaTokens.kt and NikbaComponents.kt to your Android source set. Their package is com.nikba.designsystem. Keep the Onest font resource and typography role mapping in your app.

Kotlin · Compose
import androidx.compose.foundation.isSystemInDarkTheme
import androidx.compose.material3.MaterialTheme
import androidx.compose.material3.lightColorScheme
import androidx.compose.material3.darkColorScheme
import androidx.compose.runtime.Composable
import com.nikba.designsystem.NDSColors

@Composable
fun NikbaTheme(content: @Composable () -> Unit) {
    val dark = isSystemInDarkTheme()
    val palette = if (dark) NDSColors.graphite else NDSColors.frost
    val colors = if (dark) darkColorScheme(
        background = palette.canvas, onBackground = palette.text,
        surface = palette.surface, onSurface = palette.text,
    ) else lightColorScheme(
        background = palette.canvas, onBackground = palette.text,
        surface = palette.surface, onSurface = palette.text,
    )
    MaterialTheme(colorScheme = colors, content = content)
}

This Compose example maps the canvas and surface roles. Map the remaining Material roles and your app’s typography when integrating a complete theme.

Generate and synchronize

In a checkout of the Nikba Design System repository, edit the source JSON and regenerate. Consumer directories must already exist. Updates to other repositories are explicit; --check verifies that their copies match without writing.

Terminal · Design system repository
npm run tokens:generate
npm run tokens:check
npm run test:tokens

# Synchronize tokens and components to existing app directories.
npm run native:sync -- \
  --ios-output /absolute/path/to/ios/sources \
  --android-output /absolute/path/to/android/sources

# Verify the consumer copies without writing.
npm run native:sync -- --check \
  --ios-output /absolute/path/to/ios/sources \
  --android-output /absolute/path/to/android/sources

Commit generated files alongside source changes. npm test detects stale library outputs; native:sync --check checks both tokens and handwritten components in your app. The native files are included in repository package builds; check your installed npm version for the native/ directory before using it as a source.

Platform ownership

Native behavior stays native.

CSS shadows, glass effects, fluid layout, breakpoints, and z-index remain web values. Native apps own materials, safe areas, navigation, gestures, keyboards, accessible touch targets, screen reader semantics, and reduced motion.
