01 · Architecture

One contract from source to output

The server reads only versioned files shipped with the package. It does not modify projects, call external services, or collect prompts.

Published knowledge

Hosts can discover stable URIs and read the exact documentation included in the installed package.

Principles, setup, usage, and the current public surface.

Primitive, semantic, and theme CSS custom properties.

Lifecycle and ownership boundaries for Livewire and Filament.

Native sourcenikba://native/{platform}/source/{kind}

Tokens, components, complete example, or manifest. iOS also exposes font registration and Package.swift source.

03 · Tools

Focused retrieval for AI

Every tool is read only, deterministic for a given package version, and limited to Nikba Design System files.

get_capabilities
Discover actual platform support, components, distribution, and native pilot status.
get_installation
Get setup steps, a complete first-screen URI, and the locally available iOS package path.
get_native_source
Read exact allowlisted Swift/Kotlin source and complete examples, with snapshot metadata.
list_components
Discover component names, descriptions, slugs, and resource URIs.
get_component
Read the complete contract for a component by slug.
list_documents
Discover all documentation or one component, pattern, integration, or guide category.
get_document
Read one complete document by category and slug.
get_tokens
Read web CSS layers or generated Swift/Kotlin tokens for the selected platform.
search_design_system
Find relevant guidance across the complete published system.
Platform
web · ios · android

The original six tools and build_with_nikba accept a platform argument, defaulting to web. Native requests return native contracts; missing components return available: false with a native-control fallback.

From a fresh conversation

Build your first iOS screen.

Discover iOS support, install the local Swift package, and request the same complete example compiled by the consumer test. Imports, state and focus bindings are included.

MCP tool calls · iOS
get_capabilities({ platform: "ios" })
get_installation({ platform: "ios" })
get_component({ slug: "button", platform: "ios" })
get_tokens({ platform: "ios" })
get_native_source({ platform: "ios", kind: "example" })

In Xcode, add the returned packagePath as a local development package, or use the repository URL with Exact Version 1.1.0, and link NikbaDesignSystem. The path belongs to the machine running the server. Onest is bundled and registered automatically through NDSTypography.font.

Release 1.1.0 includes published native pilot APIs. Use v1.1.0 for SwiftPM; the older web-only v1.0.0 tag does not contain the package. The sourceFingerprint matches content across MCP calls; it is not a Git revision.

Native responses include actual availability, nativeVersion, sourceFingerprint, source URIs and full example context. The iOS example and font registration are tested in an isolated SwiftPM app; Kotlin sources and the Compose example are compiled in a separate module. Both run in CI.

npm run mcp
