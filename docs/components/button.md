# Button and Icon Button

## Purpose

Button triggers an immediate action such as saving, creating, opening a control, or confirming a choice. Icon Button is the compact form used when a familiar icon can communicate the action and an accessible name is provided.

Use a link for navigation to another location. A link may use Button styling when navigation is the primary call to action, but it retains link semantics.

## Anatomy

1. Container: native `<button>` or `<a>` when navigation is intended
2. Optional leading icon
3. Visible label, except in an accessible Icon Button
4. Optional trailing icon
5. Loading indicator generated by the busy state

## Public API

| API | Purpose |
| --- | --- |
| `.nds-button` | Required base class and default Large Primary appearance |
| `.nds-button--secondary` | Supporting action with a solid surface |
| `.nds-button--ghost` | Low-emphasis action without a resting surface |
| `.nds-button--danger` | Destructive or difficult-to-reverse action |
| `.nds-button--small` | 36px dense control for pointer-first toolbars |
| `.nds-button--medium` | 44px standard compact control |
| `.nds-button--large` | 48px prominent control and default size |
| `.nds-button--block` | Fills the available inline size |
| `.nds-button--icon` | Square button; requires an accessible name |
| `.nds-button__icon` | Leading or trailing icon wrapper |
| `aria-busy="true"` | Displays the loading indicator and blocks pointer interaction |
| `aria-pressed="true|false"` | Announces and displays a toggle-button state |
| `disabled` | Native disabled state for `<button>` |
| `aria-disabled="true"` | Semantic disabled state when native `disabled` is unavailable |

## Variants

| Variant | Use when |
| --- | --- |
| Primary | The action is the main next step in its region |
| Secondary | The action supports or sits beside the primary action |
| Ghost | The action needs low emphasis in a toolbar or compact group |
| Danger | The action deletes data or causes a difficult-to-reverse change |

Use one Primary action per decision region. Multiple Primary buttons weaken hierarchy. Danger communicates consequence and does not replace a confirmation pattern when one is required.

## Sizes

| Size | Height | Guidance |
| --- | --- | --- |
| Small | 36px | Dense desktop toolbars only; provide a larger hit area on touch interfaces |
| Medium | 44px | Compact interfaces and standard touch target |
| Large | 48px | Calls to action, forms, and default use |

Icon Buttons use the same height and width. Do not make a standalone interactive target smaller than 44 by 44px on touch interfaces.

## States

| State | Visual | Behavior |
| --- | --- | --- |
| Default | Variant surface and label | Ready for activation |
| Hover | Short color change and 1px lift | Applied only on hover-capable devices |
| Active | 0.98 scale | Tracks pointer or keyboard activation |
| Focus-visible | Shared 3px focus ring | Visible for keyboard navigation |
| Pressed | Inset indicator and active scale | Requires `aria-pressed` and toggle logic |
| Loading | Spinner before the label | Requires `aria-busy="true"` and native `disabled` while pending |
| Disabled | Reduced opacity | Native `disabled` prevents activation |

## Accessibility

- Use `<button type="button">` for interface actions. Declare `type="submit"` only for form submission.
- Use `<a href>` for navigation, including prominent call-to-action links.
- Icon Buttons require `aria-label` or an equivalent accessible name.
- Decorative icons use `aria-hidden="true"` and must not repeat the visible label.
- Keep the visible label while loading so the action remains understandable. Use `aria-busy="true"` with native `disabled` while the action is pending.
- Toggle Buttons expose `aria-pressed="true"` or `false`. Do not use `aria-pressed` on ordinary action buttons.
- Prefer native `disabled`. A disabled link requires `aria-disabled="true"`, `tabindex="-1"`, and event logic that prevents activation.
- Do not use color alone to communicate a destructive or disabled state.

## Content guidance

Start labels with a concise verb: “Save changes,” “Add member,” or “Delete project.” Describe the action, not the interface element. Avoid punctuation, ambiguous labels such as “OK,” and labels that wrap to multiple lines.

Place a leading icon when it identifies the action. Place a trailing icon when it communicates direction or disclosure. Use Icon Button only for actions whose icon is familiar in context.

## Examples

Primary action:

```html
<button class="nds-button" type="button">Save changes</button>
```

Action with a leading icon:

```html
<button class="nds-button nds-button--secondary" type="button">
  <span class="nds-button__icon" aria-hidden="true">
    <!-- Consistent line icon -->
  </span>
  Add member
</button>
```

Icon Button:

```html
<button
  class="nds-button nds-button--secondary nds-button--icon nds-button--medium"
  type="button"
  aria-label="Open settings"
>
  <span class="nds-button__icon" aria-hidden="true">
    <!-- Settings icon -->
  </span>
</button>
```

Loading state:

```html
<button class="nds-button" type="button" aria-busy="true" disabled>Saving changes</button>
```

## Acceptance criteria

- All variants and sizes render in Frost, Mist, and Graphite.
- Text and icon content stay centered without layout collapse.
- Medium and Large meet the minimum touch-target height.
- Native disabled buttons cannot receive focus or activate.
- Icon Buttons expose a non-empty accessible name.
- Busy and pressed states remain distinguishable in every theme.
- Focus remains visible in standard and forced-colors modes.
- Loading animation respects reduced motion.
- Button labels do not wrap under ordinary content constraints.
