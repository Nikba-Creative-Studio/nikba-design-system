# Accessibility and Public API Audit

Audit date: September 15, 2026  
Version: `0.1.0-alpha.1`  
Standard: WCAG 2.1 AA minimum plus the repository's 44px touch-target policy

## Summary

The architecture, theme contrast, semantic catalog structure, keyboard behavior contracts, responsive snapshots, packed consumer, and documented component APIs are in substantially better condition than the September 14 baseline. The audit found two product defects and three release-verification gaps. No critical blocker was found in the tested keyboard or focus paths.

| Severity | Count | Meaning |
| --- | ---: | --- |
| Critical | 0 | No tested task is completely blocked |
| Major | 2 | Public contract or accessibility policy is incomplete |
| Minor | 1 | Documentation discovery is incomplete |
| Release verification | 2 | Requires broader browser or assistive-technology coverage |

## Findings

### A11Y-1 — Small interactive variants miss the touch-target policy

Severity: Major  
Criteria: repository policy; WCAG 2.5.5 enhanced target-size guidance

Status: Resolved in the current Unreleased changes.

`--nds-control-height-sm` is 36px. Small Button, Input, Select, Chip, Tag, Switch, menu item, pagination link, and compact navigation variants could therefore render below the 44px touch target promised by `DESIGN.md`. A final coarse-pointer layer now enforces the 44px medium control height for interactive rows and expands compact icon controls in both dimensions while preserving desktop density.

### API-1 — MCP discovery excludes product patterns and integration guides

Severity: Major

Status: Resolved in the current Unreleased changes.

The MCP server previously loaded only `docs/components`. It now publishes and searches components, patterns, integrations, and core guides through stable category URIs while preserving focused component tools. Server metadata derives its version from the packaged `package.json`.

### API-2 — JavaScript exports lack one central reference

Severity: Minor

Status: Resolved in the current Unreleased changes.

All 14 exports are now documented in one public reference with signatures, root markers, return values, events, errors, and lifecycle ownership. The API contract test checks every export against this reference, and MCP publishes it as `nikba://guides/javascript`.

### VERIFY-1 — Browser automation currently covers Chrome only

Severity: Release verification

The support target names current Chrome, Edge, Firefox, and Safari families. CI currently validates Chrome snapshots and structural accessibility. Cross-browser keyboard and layout runs remain required before `1.0.0`.

### VERIFY-2 — Manual assistive-technology matrix remains incomplete

Severity: Release verification

Browser accessibility trees expose expected landmarks, labels, status messages, and modal focus in the representative pages reviewed. VoiceOver with Safari and NVDA with Firefox or Chrome still require manual task-based verification before stable release. This limitation is already consistent with the claim boundary in `DESIGN.md`.

## Verified evidence

- Theme text contrast contracts pass across Frost, Mist, and Graphite.
- Structural checks pass for 32 catalog pages: language, main landmark, skip link, one H1, unique IDs, image alternatives, and Dialog names.
- Keyboard and lifecycle contracts pass for Accordion, Tabs, Dialog, Popover and Menu, Tooltip, Toast, Navigation, Table, Form, and dynamic DOM replacement.
- Invalid Form submission moves focus to the summary and connects visible field errors; valid submission protects duplicate requests and announces success.
- Dialog initial focus and restoration, Escape behavior, and explicit dismissal are covered by behavior tests and live browser inspection.
- Representative Overview, Form, and Destructive Confirmation pages pass desktop and compact visual thresholds without horizontal overflow.
- The built ESM exports 14 named APIs; unknown themes and glass levels throw `TypeError`.
- The packed archive builds successfully in a clean plain HTML and JavaScript consumer.
- CSS and JavaScript stay within the documented gzip budgets.

## Remediation order

1. Enforce coarse-pointer touch targets without changing desktop density.
2. Expand MCP documents and derive its version from package metadata.
3. Publish and test one JavaScript API reference.
4. Add Firefox and WebKit browser CI where the execution environment supports deterministic baselines.
5. Complete the manual VoiceOver and NVDA task matrix before the first stable release.
